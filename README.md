# NewAPI Free - 免费部署指南

在 Hugging Face Spaces 上免费部署 NewAPI，使用 Supabase 作为 PostgreSQL 数据库后端。

## 架构

```
┌─────────────┐     ┌──────────────────────┐     ┌─────────────────────┐
│  浏览器     │────▶│  HuggingFace Space   │────▶│  Supabase           │
│             │     │  NewAPI 容器         │     │  PostgreSQL 数据库  │
└─────────────┘     └──────────────────────┘     └─────────────────────┘
                           ▲                              ▲
                           │                              │
                    ┌──────┴──────────────────────────────┴──────┐
                    │              GitHub Actions                │
                    │              (自动保活 + 版本更新)          │
                    └────────────────────────────────────────────┘
```

---

## 第一步：创建 Supabase 项目

### 1.1 新建项目

1. 访问 https://supabase.com 并登录
2. 点击 **New Project**
3. 填写：
   - **Name**: `newapi-db`（或任意名称）
   - **Database Password**: 设置一个强密码，**务必记录下来**
   - **Region**: 选择离你最近的区域
4. 等待项目初始化完成（约 2 分钟）

### 1.2 创建 keep-alive 表（防止数据库暂停）

1. 项目创建完成后，左侧点击 **SQL Editor**
2. 点击 **New query**
3. 运行以下 SQL：

```sql
CREATE TABLE "keep-alive" (
  id BIGINT generated BY DEFAULT AS IDENTITY,
  name text NULL,
  created_at timestamptz DEFAULT now(),
  CONSTRAINT "keep-alive_pkey" PRIMARY KEY (id)
);
INSERT INTO "keep-alive"(name) VALUES ('ping');
```

### 1.3 获取连接信息

**数据库连接串：**

1. 进入 **Settings → Database**
2. 找到 **Connection string** 区域
3. 选择 **URI** 格式
4. 复制连接串，格式如下：
   ```
   postgresql://postgres.[项目ID]:[密码]@aws-0-[区域].pooler.supabase.com:6543/postgres
   ```
5. **重要**：将 `[密码]` 替换为你设置的数据库密码

**API 信息（用于保活）：**

1. 进入 **Settings → API**
2. 记录：
   - **Project URL**: `https://xxxxxxxx.supabase.co`
   - **anon public key**: `eyJhbGciOiJIUzI1NiIsInR5cCI6...`

## 第二步：创建 Hugging Face Space

### 2.1 新建 Space

1. 访问 https://huggingface.co/new-space
2. 填写：
   - **Space name**: `newapi-free`（或任意名称）
   - **License**: MIT
   - **SDK**: 选择 **Docker**
   - **Hardware**: 选择 **CPU basic - free**（免费）
3. 点击 **Create Space**

### 2.2 关联 GitHub 仓库

1. Space 创建后，进入 **Settings** 标签
2. 找到 **Files** 区域
3. 点击 **Link your GitHub repository**
4. 选择你的 `newapi-free` 仓库
5. 保存后，HF 会自动拉取代码并构建

---

## 第三步：配置 Hugging Face Secrets

在 Space 的 **Settings → Variables and secrets** 中添加：

### 3.1 Secrets（敏感信息，不显示在日志中）

| Name | Value | 说明 |
|------|-------|------|
| `SQL_DSN` | 见下方格式 | Supabase 数据库连接串 |
| `SESSION_SECRET` | 随机字符串 | Session 加密密钥，如 `my-super-secret-key-123` |

**SQL_DSN 格式：**

```
postgres://postgres.[项目ID]:[密码]@aws-0-[区域].pooler.supabase.com:6543/postgres?sslmode=require
```

> 注意末尾添加 `?sslmode=require` 以启用 SSL 连接

**示例：**
```
postgres://postgres.abcdefghijk:MyP@ssw0rd@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres?sslmode=require
```

### 3.2 Variables（普通配置）

| Name | Value |
|------|-------|
| `PORT` | `7860` |
| `TZ` | `Asia/Shanghai` |

## 第四步：配置 GitHub Secrets

在你的 GitHub 仓库中，进入 **Settings → Secrets and variables → Actions**：

### 4.1 Secrets

| Name | Value | 用途 |
|------|-------|------|
| `HF_TOKEN` | HF 写权限令牌 | 推送到 HF Space |
| `SUPABASE_URL` | `https://xxxxxxxx.supabase.co` | Supabase 保活 |
| `SUPABASE_KEY` | `eyJhbGciOiJIUzI1NiIs...` | Supabase 保活 |

**获取 HF_TOKEN：**
1. 访问 https://huggingface.co/settings/tokens
2. 创建新令牌，选择 **Write** 权限

### 4.2 Variables

| Name | Value | 用途 |
|------|-------|------|
| `HF_SPACE_URL` | `https://你的用户名-newapi-free.hf.space` | HF Space 保活 |

## 第五步：部署完成

### 5.1 访问 NewAPI

- 地址：`https://<你的HF用户名>-<space名称>.hf.space`
- 默认账号：`root`
- 默认密码：`123456`

**⚠️ 首次登录后请立即修改密码！**

### 5.2 验证数据库连接

登录 NewAPI 后，创建一个渠道或令牌，如果成功保存，说明数据库连接正常。

## 密码特殊字符处理

如果数据库密码包含特殊字符，需要进行 URL 编码：

| 字符 | 编码 |
|------|------|
| `@` | `%40` |
| `#` | `%23` |
| `%` | `%25` |
| `&` | `%26` |
| `+` | `%2B` |
| `=` | `%3D` |
| `/` | `%2F` |
| `?` | `%3F` |

示例：密码 `P@ss#123` 应编码为 `P%40ss%23123`

## 自动保活机制

GitHub Actions 会每日 UTC 3:00（北京时间 11:00）自动执行：

- **Hugging Face 保活**：访问你的 Space URL
- **Supabase 保活**：查询 `keep-alive` 表

防止免费服务因闲置被暂停。

## 手动更新 NewAPI 版本

1. 进入 GitHub 仓库的 **Actions** 标签
2. 选择 **Check for NewAPI Updates and Sync to Hugging Face Space**
3. 点击 **Run workflow**
4. 等待执行完成

---

## 故障排查

### Space 无法访问 (502)

1. 查看 Space 的 **Logs**
2. 检查 `SQL_DSN` 格式是否正确
3. 确认密码中的特殊字符已编码
4. 确认 Supabase 项目未暂停

### 数据库连接失败

1. 检查连接串末尾是否有 `?sslmode=require`
2. 确认 Supabase 项目状态
3. 在 Supabase 的 **Database Settings** 中检查连接池设置

### 服务被暂停

1. 检查 GitHub Actions 是否正常运行
2. 确认 Secrets 和 Variables 配置正确
