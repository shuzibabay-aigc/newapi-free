# NewAPI Free

This repository provides a template for deploying a free, self-updating instance of [NewAPI](https://github.com/Calcium-Ion/new-api) on [Hugging Face Spaces](https://huggingface.co/spaces), using [Supabase](https://supabase.com/) as the database backend.

NewAPI is an OpenAI API management and distribution system that allows you to manage multiple API keys and distribute them through a unified interface.

## Architecture

```
┌─────────────────┐     ┌──────────────────────────┐     ┌─────────────────────────┐
│   Your Browser  │────▶│  HuggingFace Space       │────▶│  Supabase PostgreSQL    │
│                 │     │  NewAPI Container        │     │  Database               │
└─────────────────┘     └──────────────────────────┘     └─────────────────────────┘
                              ▲                                    ▲
                              │                                    │
                        ┌─────┴────────────────────────────────────┴─────┐
                        │           GitHub Actions                        │
                        │           (Keep-Alive Tasks)                    │
                        └────────────────────────────────────────────────┘
```

## Features

- **Free Hosting**: Deploy on Hugging Face Spaces (free CPU tier)
- **Free Database**: Use Supabase PostgreSQL (free tier)
- **Auto Keep-Alive**: GitHub Actions prevent services from being paused
- **Auto Update**: Automatically check and update NewAPI version

## Deployment Guide

### 1. Fork the Repository

Fork this repository to your own GitHub account.

### 2. Create a Supabase Project

1. Go to [Supabase](https://supabase.com/) and create a new project.
2. Once the project is created, navigate to the **SQL Editor**.
3. Run the following SQL to create a `keep-alive` table:

    ```sql
    CREATE TABLE "keep-alive" (
      id BIGINT generated BY DEFAULT AS IDENTITY,
      name text NULL,
      created_at timestamptz DEFAULT now(),
      CONSTRAINT "keep-alive_pkey" PRIMARY KEY (id)
    );
    INSERT INTO "keep-alive"(name) VALUES ('ping');
    ```

4. Navigate to **Project Settings > API** and note down:
   - **Project URL**
   - **anon public** API key

5. Navigate to **Project Settings > Database**:
   - Find the **Connection string** (URI format)
   - Replace `[YOUR-PASSWORD]` with your database password

### 3. Create a Hugging Face Space

1. Go to [Hugging Face Spaces](https://huggingface.co/new-space) and create a new Space.
2. Select **Docker** as the Space SDK.
3. Choose **CPU basic** (free tier).
4. After creation, go to **Settings** and link your forked GitHub repository.

### 4. Configure Hugging Face Space Secrets

Add the following secrets in your Space Settings:

| Secret | Description | Example |
|--------|-------------|---------|
| `SQL_DSN` | Supabase PostgreSQL connection string | `postgresql://postgres:password@db.xxxxx.supabase.co:5432/postgres` |
| `SESSION_SECRET` | Session encryption key | `your-random-secret-string` |

### 5. Configure Hugging Face Space Variables

Add the following variables in your Space Settings:

| Variable | Value | Description |
|----------|-------|-------------|
| `PORT` | `7860` | Required by HF Spaces |
| `TZ` | `Asia/Shanghai` | Timezone (optional) |

### 6. Configure GitHub Repository Secrets

In your forked repository, go to **Settings > Secrets and variables > Actions**:

**Secrets:**

| Secret | Description |
|--------|-------------|
| `HF_TOKEN` | Hugging Face token with write permission |
| `SUPABASE_URL` | Your Supabase Project URL |
| `SUPABASE_KEY` | Your Supabase anon public API key |

**Variables:**

| Variable | Description | Example |
|----------|-------------|---------|
| `HF_SPACE_URL` | Your Hugging Face Space URL | `https://username-newapi-free.hf.space` |

### 7. Deploy and Access

1. After configuration, Hugging Face will automatically build and deploy your Space.
2. Access your NewAPI instance at: `https://<username>-<space-name>.hf.space`
3. Default credentials: `root` / `123456` (change immediately after first login)

## How It Works

### Automatic NewAPI Updates

The `update-newapi.yml` workflow can be triggered manually to:

1. Check the latest NewAPI release version from GitHub
2. Compare with the current version in Dockerfile
3. Update Dockerfile if a new version is found
4. Push changes to GitHub and Hugging Face Space

### Keep-Alive Services

Both Hugging Face Spaces and Supabase free tiers pause after inactivity. The keep-alive workflows prevent this:

- **Hugging Face Keep-Alive**: Sends daily HTTP requests to your Space
- **Supabase Keep-Alive**: Queries the `keep-alive` table daily

Both run at UTC 03:00 daily via cron schedule.

## Configuration Reference

### NewAPI Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `SQL_DSN` | Yes | PostgreSQL connection string |
| `SESSION_SECRET` | Yes | Session encryption key |
| `PORT` | Yes | Server port (7860 for HF Spaces) |
| `TZ` | No | Timezone setting |
| `REDIS_CONN_STRING` | No | Redis connection (optional, for caching) |

### GitHub Actions Secrets

| Secret | Used By | Description |
|--------|---------|-------------|
| `HF_TOKEN` | update-newapi.yml | Hugging Face write token |
| `SUPABASE_URL` | supabase-keep-alive.yml | Supabase project URL |
| `SUPABASE_KEY` | supabase-keep-alive.yml | Supabase anon public key |

### GitHub Actions Variables

| Variable | Used By | Description |
|----------|---------|-------------|
| `HF_SPACE_URL` | huggingface-keep-alive.yml | Your Space URL |

## Troubleshooting

### Space Not Accessible (502 Error)

- Check Space logs for errors
- Verify `SQL_DSN` is correctly formatted
- Ensure Supabase project is not paused

### Supabase Connection Failed

- Verify connection string format
- URL-encode special characters in password
- Check if SSL is required

### Services Getting Paused

- Verify GitHub Actions are running successfully
- Check that secrets and variables are correctly set

## Notes

- Free tier limitations apply to both Hugging Face and Supabase
- Regular backups of your Supabase database are recommended
- Change the default password immediately after first login
